# MVT 空间表服务目录

管理端新增 **MVT 空间表服务**，路由为 `/land/mvt/services`。页面自动发现已配置 PostgreSQL 数据库中账号有权读取的空间表和视图，并提供 TileJSON 与 XYZ 地址。瓦片由 Java 后端调用 PostGIS 生成，不依赖 Martin。

## 日常使用

1. 使用管理员账号打开管理端，进入「MVT 空间表服务」。本次本地运行入口为 `http://localhost:3006/land/mvt/services`（开发服务器默认尝试 3000，已被占用时会递增端口，以实际启动日志为准）。
2. 选择 PostgreSQL 数据库。当前已配置「经营性用地空间库」，连接编码为 `land_postgis`。
3. 新增空间表后点击「刷新发现」，即可获得服务地址，无需逐表注册或发布。目录也会在下次请求且缓存超过 5 分钟时自动重新发现。
4. 新增数据库时，点击「添加数据库」填写连接编码、名称、JDBC 地址、数据库名称、账号与密码，保存后即可选择该库。复用系统原有多数据源管理，口令按原有机制存储。
5. 服务地址自动取管理端的 Java API 配置 `window._CONFIG.domianURL`（含 `/api`）。部署时应将该配置设为地图客户端可访问的服务器 IP 或域名；若复制的地址为 `127.0.0.1` 或 `localhost`，供其他电脑使用前需替换成服务器 IP 或域名。
6. 每个空间表或视图以卡片展示，点击「复制地址」可直接复制 TileJSON 地址；点击表名或「查看详情」，可查看完整描述及 TileJSON、XYZ 两种地址并分别复制。到中台按现有流程配置 MVT 资源、审批和图层树。

## 地址格式

TileJSON：

```text
http://服务器IP:9802/api/land/mvt/public/连接编码/schema/表名/几何列
```

XYZ：

```text
http://服务器IP:9802/api/land/mvt/public/连接编码/schema/表名/几何列/{z}/{x}/{y}.pbf
```

路径带连接编码、schema 和几何列，用于区分不同数据库、不同 schema 的同名表，以及一张表的多个几何列。链接由页面自动编码生成。瓦片采用 XYZ、Web Mercator、层级 0～22；MVT 内部图层名为表名，TileJSON 的 `vector_layers` 中也会返回。

当前经营性用地发布视图的本机 TileJSON 地址为：

```text
http://127.0.0.1:9802/api/land/mvt/public/land_postgis/public/jyxyd_dk_mvt/geom
```

当前原表 `jyxyd_dk_geom` 声明的 SRID 为 4547，但已有数据的实际坐标对应 4548。请使用已存在的 `jyxyd_dk_mvt` 视图地址。目录显示“坐标系已声明”只表示 SRID 已声明且存在于坐标系目录中，不代表系统能够判断原始数据的标注是否正确。

## 数据要求与范围

- PostgreSQL 数据库需要安装 PostGIS 3 或以上版本。
- 自动发现普通表、分区表、视图和物化视图的 geometry / geography 列；多个几何列分别列出。系统 schema 不展示。
- 连接账号需要相应 schema 的 USAGE 和表的 SELECT 权限。仅扫描已在管理端配置的 PostgreSQL 数据库，不会自动连接其他数据库。
- 几何列必须有明确、有效的 SRID 类型声明；未声明时页面会列出原因。可使用带明确几何类型和 SRID 的发布视图，不会自动猜测或改写原表。
- 服务输出表中可支持的数值、文本、布尔和日期等属性，排除其他几何列及二进制等字段。公开瓦片可由无需登录的地图客户端访问，因此数据库连接账号应只授予适合公开给地图客户端的数据读取权限。
- 建议来源几何列建立空间索引。低缩放层级涉及较大范围，仍可能扫描较多数据；单次 SQL 查询超时为 10 秒。查询通过 `OFFSET 0` 避免坐标转换、裁剪在非空过滤和编码阶段重复执行，保持原有几何与属性输出。
- 数据源白名单缓存 30 秒，管理目录读取实时核对已配置数据库；空间表目录缓存 5 分钟，按数据库分别重建，慢库不会占住所有数据库的目录锁。TileJSON 按需计算范围，并随目录缓存；空表、非法范围或计算超时时省略 bounds。
- 单个 Java 进程内提供 64 MiB 的瓦片字节缓存，每项至少按 16 KiB 计权，最多约 4096 项，空瓦片也占名额。瓦片自写入起 30 秒过期，超大瓦片不缓存；相同瓦片的并发请求只执行一次 SQL，失败结果不缓存。多实例各自缓存，尚未预生成或跨实例共享。
- 「刷新发现」立即重建所选数据库目录、清除对应服务端旧瓦片及范围缓存；在途旧请求不能污染新目录。HTTP 缓存仍为 30 秒，服务端与浏览器缓存时间可能叠加。浏览器已缓存或地图已加载的内容，需要等缓存过期后重新请求，或重新加载图层/页面。
- 可用 Druid 池直接在本地复用，正常瓦片请求不再反复查询 Redis 连接配置。连接配置被系统管理端修改、旧池关闭后，下次未命中瓦片缓存的查询会重新获取池。
- 开发、测试、生产环境的压缩 MIME 列表均已包含 MVT 与 protobuf；客户端接受 gzip 且响应超过既有 1024 字节门槛时由服务器压缩。

## 部署与验证

1. 部署 Java 后端新增的 `land/map/mvt` 代码和 Shiro 精确匿名路径 `/land/mvt/public/**`；目录管理接口仍要求登录且具有 admin 角色。
2. 在应用实际使用的 MySQL 数据库执行 `server/jeecg-module-land/src/main/resources/sql/map/01_mvt_service_menu.sql`。脚本可重复执行，并为 admin 角色增加菜单。
3. 部署 admin-client，重启 Java，并重新登录或刷新管理端菜单。
4. 配置 PostgreSQL 连接，检查页面列表以及 TileJSON、PBF 地址。跨域地图访问由服务的 CORS 配置支持。

## 2026-10-28 性能优化验证

使用同一发布视图 `jyxyd_dk_mvt`、瓦片 `8/211/97` 做只读诊断，优化后 PBF 仍为 44239 字节，与此前响应逐字节相同。

| 验证范围 | 结果 |
|---|---|
| 实际 PostGIS，原 SQL，3 次直接查询 | 677～709 ms |
| 实际 PostGIS，避免重复裁剪的 SQL，3 次直接查询 | 328～355 ms，二进制结果相同 |
| 优化后 Java 服务方法，1000 次缓存命中 | 中位数约 0.005 ms；合计仅 1 次来源配置查询、1 次连接配置加载和 1 次瓦片 SQL |
| 8 个相同瓦片的并发请求，真实 PostGIS | 仅执行 1 次瓦片 SQL，所有结果相同 |

以上为临时诊断程序直接调用编译后的服务代码，没有启动另一个后端。它不包含 HTTP、Redis 首次建池或浏览器绘制开销；不能拿方法耗时当作在线接口或地图帧率。未缓存的大范围瓦片仍受几何数量和顶点数影响，查询计划显示当前发布视图会扫描原表。

本次优化最终验证：18 项针对性测试全部通过（含 3 项真实 PostGIS 测试，测试数据事务回滚），完整启动模块及全部上游依赖编译通过。最终编译产物直接查询该瓦片 6 次为 317～327 ms；8 并发相同新瓦片约 132 ms，只有一次 SQL。首个服务方法调用包含来源查询和目录发现仍约 858 ms，缓存加速主要作用于后续请求。

需要在 IDE 中重启原有 Java 后端，再刷新地图页面，才能让现有 9802 进程应用本次代码与压缩配置。当前运行进程未被自动重启，因此尚未测量优化后的在线 HTTP 耗时和 gzip 响应。

## 2026-10-28 首次加载二次优化

后台复用反投影窗口；第 8 级及以上，对明确声明为 LineString/Polygon 及其 Multi 类型的 geometry，在原坐标系用窗口短边的 1/(4096×64) 容差去掉极近的相邻顶点，再转 3857、裁剪及编码。原始几何和发布视图不变。第 0～7 级继续使用原顶点，避免改变量化临界小面的取舍；点、多点、集合、曲线、geography、3857 及正投影兜底保持原路径。这是显示精度优化，少数编码坐标可能改变，不再保证与第一轮逐字节相同。

同一只读连接交替执行、数据库缓存预热后、绕过 Java 瓦片缓存的实测：

| 瓦片 | 第一轮 SQL | 第二轮 SQL |
|---|---|---|
| 8/211/97 | 364～369 ms | 125～127 ms |
| 9/422/195 | 245～257 ms | 118～120 ms |
| 9/423/195 | 141～150 ms | 72～74 ms |
| 14/13536/6273 | 约 10 ms | 约 10 ms |

第 8 级样例保留 1055 个输出要素及全部属性、1084 个环；上述第 8/9/14 级样本双向顶点到边的最大轮廓差为 0.0625 个画布像素。粗层级已退回原始路径。这些测量不含 HTTP 和地图绘制，不能视为在线端到端耗时，也不能与 Martin 的热缓存响应直接比较。

前端同步按 TileJSON 范围选择起始层级（最多四张根瓦片、最高 8 级）；天津概览浏览器实测只请求三张第 8 级瓦片，不再请求第 1～7 级父瓦片。资源已有显式 minimumLevel 时优先采用其设置。缓存有效期仍为 30 秒。后端必须在用户原有 IDE 进程重启后才生效，本轮不启动或重启服务。

最终验证：19 项针对性测试全部通过（含 4 项真实 PostGIS 测试，测试数据事务回滚）；完整启动模块及上游依赖编译成功。前端 ESLint、84 个 SFC 编译自检及浏览器交互检查通过。第 5/8/9/14 级共五张真实瓦片的要素、属性、环数量核对通过，第 5 级仍保留 451 个要素、454 个环且轮廓无差异。最终编译产物重复测得第 8 级原路径 347～354 ms、新路径 117～138 ms，简单第 14 级仍约 9 ms；在线 HTTP 和完整地图加载时间尚待原有服务重启后核验。
